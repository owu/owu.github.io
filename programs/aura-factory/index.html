Aura Factory Development Manual

2025/12/25 · 1171 words · 6 minutes to read
Categories: Rust
Tags: Slint GUI

Aura Factory is a free and open-source desktop audio/video conversion tool developed based on the Rust language. It uses the modern GUI framework Slint to build the user interface and leverages FFmpeg as the underlying audio/video processing engine.

Aura Factory demonstrates the complete technology stack for modern Rust desktop application development, combining a high-performance system programming language with a modern GUI framework.

Project Overview 🔗

Core Features 🔗

  • Supports multiple audio/video format conversions
  • Provides advanced features like video cropping, resolution adjustment, frame rate settings, etc.
  • Cross-platform support (Windows/Linux)
  • Real-time progress display and conversion status monitoring
  • Version expiration detection mechanism

Technical Architecture 🔗

Overall Architecture Diagram 🔗

┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│    UI Layer     │    │   Business Logic │    │   FFmpeg Layer  │
│  (Slint GUI)    │◄──►│   (Rust Core)    │◄──►│  (Sidecar)      │
└─────────────────┘    └─────────────────┘    └─────────────────┘

Technology Stack 🔗

  • Programming Language: Rust 2024 Edition
  • GUI Framework: Slint 1.14.1
  • Audio/Video Processing: FFmpeg-sidecar 2.3.0
  • Async Runtime: Tokio 1.x
  • HTTP Client: Reqwest
  • File Dialog: RFD
  • Serialization: Serde
  • Time Handling: Chrono

Core Module Details 🔗

1. Main Program Module (main.rs) 🔗

Main Functions:

  • Application initialization and lifecycle management
  • User interface event handling
  • Asynchronous task scheduling
  • Version expiration detection

Key Implementation:

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // FFmpeg automatic download check
    ffmpeg_sidecar::download::auto_download()?;
    
    // Create Slint application instance
    let app = App::new()?;
    
    // Network time acquisition (for expiration detection)
    let network_timestamp = Arc::new(AtomicI64::new(0));
    tokio::spawn(async move {
        let ts = utils::time::standard_time();
        network_timestamp.store(ts, Ordering::Relaxed);
    });
    
    // File selection callback
    app.on_select_file(move || {
        // Use RFD to open file dialog
        if let Some(path) = FileDialog::new().pick_file() {
            // Asynchronously analyze media file information
            tokio::spawn(async move {
                match media::probe_media_info(&path_str).await {
                    Ok((duration_str, info_str, _)) => {
                        // Update UI display
                        app.set_total_duration(duration_str.into());
                    }
                    Err(e) => { /* Error handling */ }
                }
            });
        }
    });
    
    app.run()?;
    Ok(())
}

2. Media Analysis Module (media.rs) 🔗

Main Functions:

  • Use FFprobe to analyze media file metadata
  • Extract video/audio stream information
  • Format display information

Data Structures:

#[derive(Deserialize, Debug)]
pub struct ProbeResult {
    pub format: Format,
    pub streams: Vec<Stream>,
}

#[derive(Deserialize, Debug)]
pub struct Stream {
    pub codec_type: String,        // "video" or "audio"
    pub width: Option<i32>,        // Video width
    pub height: Option<i32>,       // Video height
    pub r_frame_rate: Option<String>, // Frame rate
    pub bit_rate: Option<String>,  // Bitrate
    pub sample_rate: Option<String>, // Audio sample rate
    pub codec_name: Option<String>, // Codec name
}

**Key Functions**:
- `probe_media_info()`: Analyze media file and return formatted information
- `get_probe_result()`: Execute FFprobe command and parse JSON output

### 3. Conversion Processing Module (conversion.rs)

**Main Functions**:
- Build and execute FFmpeg conversion commands
- Real-time progress monitoring
- Conversion cancellation support

**Core Conversion Process**:
```rust
pub async fn run_conversion(
    input: String,          // Input file path
    format: String,         // Output format
    start: String,          // Start time

Progress Monitoring Mechanism:

  • Get conversion progress through FFmpeg’s progress events
  • Calculate percentage based on expected duration
  • Real-time update of UI progress bar and status information

User Interface Design 🔗

Interface Architecture 🔗

Using Slint declarative UI framework, main components include:

  1. Main Window (App): Base component inherited from Window
  2. Card Component (Card): Reusable content container
  3. Tab Button (TabButton): Tab switching control

Interface Layout 🔗

  • Top: Logo and title area
  • Middle: Tab navigation (General/Output Settings)
  • Bottom: File selection, conversion control, progress display

State Management 🔗

Manage application state through Slint’s in-out property mechanism:

  • selected-file: Currently selected file path
  • progress: Conversion progress (0.0-1.0)
  • is-converting: Whether conversion is in progress
  • status-message: Status prompt information

Windows Build 🔗

  1. Clean previous builds
  2. Use cargo build to compile release version
  3. Extract version number from consts.rs
  4. Rename executable file

Linux Build 🔗

# Use build.sh script

Build process:

  1. Create standard Linux package structure
  2. Generate desktop files and icons
  3. Create installation/uninstallation scripts

Build Configuration Optimization 🔗

Optimized release build configuration in Cargo.toml:

[profile.release]
opt-level = "z"      # Minimize code size
lto = true          # Link-time optimization
codegen-units = 1   # Single code generation unit
strip = true        # Remove debug symbols
panic = "abort"     # Direct termination on panic

Key Technical Features 🔗

1. Asynchronous Processing Architecture 🔗

  • Use Tokio runtime to handle file analysis and conversion tasks
  • Separate UI thread from background tasks to avoid interface lag
  • Callback-based event-driven model

2. Error Handling Mechanism 🔗

  • Use Anyhow library for unified error handling
  • Detailed error information feedback to users
  • Graceful failure recovery mechanism

3. Resource Management 🔗

  • Use Arc and Atomic types for thread-safe data sharing
  • Weak references to avoid memory leaks from circular references
  • Timely resource release and cleanup

4. Cross-Platform Compatibility 🔗

  • Conditional compilation to handle platform differences (e.g., Windows icon resources)
  • Unified file path handling
  • Platform-specific build scripts

Performance Optimization 🔗

Build Optimization 🔗

  • Enable LTO (Link-Time Optimization) to reduce binary size
  • Use minimal optimization level (-Oz)
  • Remove debug symbols and redundant code

Runtime Optimization 🔗

  • Asynchronous tasks avoid blocking UI thread
  • Reasonable memory allocation and deallocation
  • Efficient string processing

Security Considerations 🔗

Input Validation 🔗

  • File path security checks
  • Time format validity verification
  • Parameter boundary checks

Resource Access 🔗

  • File read/write permission control
  • Network request timeout settings
  • Memory safety guarantee (Rust ownership system)

Extensibility Design 🔗

Modular Architecture 🔗

  • Clear module boundaries and responsibility separation
  • Easy to add new file format support
  • Extensible conversion parameter configuration

Configuration-Based Design 🔗

  • Centralized constant management for easy maintenance
  • Parameterized build process
  • Configurable interface elements

Known Limitations and Future Improvements 🔗

Current Limitations 🔗

  1. Dependency on external FFmpeg binaries
  2. Relatively basic conversion parameter configuration
  3. Limited batch processing support

Improvement Directions 🔗

  1. Integrate more audio/video processing features
  2. Add preset configuration templates
  3. Support batch file processing
  4. Enhance error recovery and retry mechanisms

Summary 🔗

The project adopts a reasonable architecture design with good maintainability and extensibility. Through detailed code analysis and modular design, it lays a solid foundation for subsequent feature expansion.
