Hugo static blog deployment script

2025/12/26 · 1180 words · 3 minutes to read

这两个部署脚本提供了一个完整的 Hugo 博客自动化部署解决方案。通过清晰的步骤划分、完善的错误处理和跨平台支持，用户可以轻松地将本地 Hugo 项目部署到 GitHub Pages。

脚本采用双仓库策略：私有仓库存放 Hugo 源代码，公有仓库只存放生成的静态文件，确保源代码安全的同时实现自动化部署。

📎 Linux/macOS 部署脚本 (deploy.sh)
📎 Windows 部署脚本 (deploy.ps1)

环境配置 🔗

仓库设置 🔗

采用双仓库策略：

SRC_DIR (Hugo 项目目录)

  • 私有仓库，包含 Hugo 源代码和配置文件
  • 仓库名称示例：owu.github.com（可自定义）
  • 包含 config.toml、content/、themes/ 等 Hugo 项目文件

DST_DIR (GitHub Pages 目录)

  • 公有仓库，只包含 Hugo 生成的静态文件
  • 仓库名称格式：username.github.io（GitHub Pages 要求）
  • 通过 GitHub Pages 公开访问

路径配置 🔗

使用前需根据实际环境修改脚本中的路径变量：

deploy.ps1 (Windows):

$SRC_DIR = "D:\develop\owu.github.com"
$DST_DIR = "D:\develop\owu.github.io"

deploy.sh (Linux):

SRC_DIR="/home/develop/owu.github.com"
DST_DIR="/home/develop/owu.github.io"

环境要求 🔗

  • Git 版本控制工具
  • Hugo 静态网站生成器
  • 对两个仓库的读写权限

部署流程 🔗

脚本自动完成以下9个步骤：

  1. 更新源代码仓库 - 切换到 main 分支，拉取最新代码
  2. 生成静态文件 - 执行 hugo build 生成静态文件
  3. 导出干净文件 - 使用 git archive 导出版本控制的文件
  4. 更新目标仓库 - 切换到 GitHub Pages 仓库并拉取最新代码
  5. 清理目标目录 - 删除除 .git 文件夹外的所有内容
  6. 复制静态文件 - 将生成的静态文件复制到目标目录
  7. 清理临时文件 - 删除临时创建的目录
  8. 提交推送更改 - 提交并推送到远程仓库
  9. 返回原始目录 - 切换回源代码目录

两个脚本功能相同，主要差异在：

特性 deploy.ps1 (Windows) deploy.sh (Linux)
路径格式 Windows 格式 (D:\) Unix 格式 (/)
命令语法 PowerShell 命令 Bash 命令
临时目录 New-TemporaryFile mktemp -d
错误检查 $LASTEXITCODE $?
文件操作 Get-ChildItem, Remove-Item find, rm

两个脚本都提供完善的错误处理和详细执行日志。

使用方法 🔗

Windows 环境 🔗

# 进入 Hugo 项目目录
cd D:\develop\owu.github.com

# 执行部署脚本
.\deploy.ps1

Linux/Unix 环境 🔗

# 进入 Hugo 项目目录  
cd /home/develop/owu.github.com

# 给脚本添加执行权限
chmod +x deploy.sh

# 执行部署脚本
./deploy.sh

执行后观察脚本输出的进度信息，绿色表示成功，红色表示错误。

常见问题 🔗

部署失败原因 🔗

Git 相关错误

  • 切换分支失败: 当前分支有未提交的更改 → 提交或暂存所有更改
  • 拉取代码失败: 网络连接问题或远程仓库不可达 → 检查网络和远程仓库配置

Hugo 相关错误

  • 生成失败: Hugo 配置错误或缺少依赖 → 运行 hugo server 测试本地生成

路径相关错误

  • 目录不存在或权限不足: 路径配置错误或权限问题 → 检查路径和权限设置

调试技巧 🔗

  1. 手动测试: hugo build 测试生成，git status 检查 Git 状态
  2. 检查临时文件: 脚本失败时保留临时目录用于调试
  3. 查看详细日志: 关注红色错误信息定位问题

注意事项 🔗

  • 执行前确保所有更改已提交到源代码仓库
  • 脚本会强制重置本地更改，确保与远程仓库一致
  • 目标仓库的 .git 目录会被保留，其他内容会被完全替换
  • 建议在部署前先进行本地测试（hugo server）

总结 🔗

主要优势：

  • 🚀 完全自动化部署流程
  • 🔒 安全的双仓库策略，保护源代码
  • 💻 跨平台兼容性（Windows/Linux）
  • 🐛 完善的错误处理和调试信息

使用建议：

  1. 首次使用前仔细阅读配置说明
  2. 按照环境配置设置正确的仓库和路径
  3. 遇到问题时参考常见问题部分
