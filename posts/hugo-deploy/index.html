Hugo static blog deployment script

2025/12/26 · 617 words · 3 minutes to read

These two deployment scripts provide a complete automated deployment solution for Hugo blogs. With clear step-by-step processes, comprehensive error handling, and cross-platform support, users can easily deploy local Hugo projects to GitHub Pages.

The scripts use a dual-repository strategy: private repository stores Hugo source code, while public repository only contains generated static files, ensuring source code security while enabling automated deployment.

📎 Linux/macOS Deployment Script (deploy.sh)
📎 Windows Deployment Script (deploy.ps1)

Environment Configuration 🔗

Repository Setup 🔗

Using a dual-repository strategy:

SRC_DIR (Hugo Project Directory)

  • Private repository containing Hugo source code and configuration files
  • Repository name example: owu.github.com (customizable)
  • Contains Hugo project files like config.toml, content/, themes/, etc.

DST_DIR (GitHub Pages Directory)

  • Public repository containing only Hugo-generated static files
  • Repository name format: username.github.io (GitHub Pages requirement)
  • Publicly accessible through GitHub Pages

Path Configuration 🔗

Before using, modify the path variables in the scripts according to your actual environment:

deploy.ps1 (Windows):

$SRC_DIR = "D:\develop\owu.github.com"
$DST_DIR = "D:\develop\owu.github.io"

deploy.sh (Linux):

SRC_DIR="/home/develop/owu.github.com"
DST_DIR="/home/develop/owu.github.io"

Environment Requirements 🔗

  • Git version control tool
  • Hugo static site generator
  • Read/write permissions for both repositories

Deployment Process 🔗

The scripts automatically complete the following 9 steps:

  1. Update Source Code Repository - Switch to main branch and pull latest code
  2. Generate Static Files - Execute hugo build to generate static files
  3. Export Clean Files - Use git archive to export version-controlled files
  4. Update Target Repository - Switch to GitHub Pages repository and pull latest code
  5. Clean Target Directory - Delete all content except .git folder
  6. Copy Static Files - Copy generated static files to target directory
  7. Clean Temporary Files - Delete temporarily created directories
  8. Commit and Push Changes - Commit and push to remote repository
  9. Return to Original Directory - Switch back to source code directory

Both scripts have the same functionality, with main differences in:

Feature deploy.ps1 (Windows) deploy.sh (Linux)
Path Format Windows format (D:\) Unix format (/)
Command Syntax PowerShell commands Bash commands
Temporary Directory New-TemporaryFile mktemp -d
Error Checking $LASTEXITCODE $?
File Operations Get-ChildItem, Remove-Item find, rm

Both scripts provide comprehensive error handling and detailed execution logs.

Usage Instructions 🔗

Windows Environment 🔗

# Navigate to Hugo project directory
cd D:\develop\owu.github.com

# Execute deployment script
.\deploy.ps1

Linux/Unix Environment 🔗

# Navigate to Hugo project directory  
cd /home/develop/owu.github.com

# Add execute permission to the script
chmod +x deploy.sh

# Execute deployment script
./deploy.sh

After execution, observe the script’s progress output - green indicates success, red indicates errors.

Common Issues 🔗

Deployment Failure Reasons 🔗

Git-related Errors

  • Branch Switch Failed: Current branch has uncommitted changes → Commit or stash all changes
  • Code Pull Failed: Network connection issues or remote repository unreachable → Check network and remote repository configuration

Hugo-related Errors

  • Generation Failed: Hugo configuration errors or missing dependencies → Run hugo server to test local generation

Path-related Errors

  • Directory Doesn’t Exist or Insufficient Permissions: Path configuration errors or permission issues → Check path and permission settings

Debugging Tips 🔗

  1. Manual Testing: Test generation with hugo build, check Git status with git status
  2. Check Temporary Files: Temporary directories are preserved when scripts fail for debugging
  3. View Detailed Logs: Focus on red error messages to identify problems

Important Notes 🔗

  • Ensure all changes are committed to the source code repository before execution
  • Scripts will forcibly reset local changes to ensure consistency with remote repository
  • The .git directory in the target repository will be preserved, all other content will be completely replaced
  • It’s recommended to perform local testing (hugo server) before deployment
